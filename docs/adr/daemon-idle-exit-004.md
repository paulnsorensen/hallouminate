# ADR — daemon-idle-exit-004

### ADR-004: Only inference-bearing work restarts the idle-exit window  [status: accepted]

- **Context:** ADR-003 stamps the idle clock at every request completion. With N concurrent agent sessions, cheap `list_corpora`, status, and read RPCs arrive more often than `idle_exit_secs`, so the daemon never exits and the ONNX arena never returns memory (#222). ADR-003 rejected an embed-only clock for two reasons: exit under active non-embed use, and exit during a write. The `ConnectionGuard` counter and the bounded handler drain now cover the second reason for every request class.
- **Decision:** `touch_activity(WorkClass, IdleClock)` takes an explicit `IdleClock::{Restart, Keep}`. Successful `ground`, `index`, and `add_markdown` RPCs restart the window; dispatch errors keep it. Watcher and boot catch-up passes restart it only when `ApplyStats::embeddings_inserted > 0`; no-op, delete-only, cleanup, and failed passes keep it. The per-class clock moves for both values, so maintenance-defer still sees every external request. Crossencoder acquisition and guard drop continue to stamp the idle clock; a timed-out rerank may drop its blocking task's guard after the response. No embedder guard stamps the daemon clock. `idle_clock_for` classifies `DaemonRequestPayload` with an exhaustive match, so a new RPC must declare its effect.
- **Evidence:** Bazel (`--max_idle_secs`), sccache (`SCCACHE_IDLE_TIMEOUT`), and the Gradle daemon count build or compile work toward idleness, not status traffic. sccache issue #204 and systemd issue #2106 show that exit-on-idle must track in-flight work explicitly; the connection counter does this. An ONNX Runtime maintainer states that arena shrinkage targets GPU memory (onnxruntime #23339), so process exit stays the reclaim mechanism. Full claim table: `.cheese/research/idle-exit-policy/idle-exit-policy.md`.
- **Alternatives:** Memory-threshold or maximum-lifetime recycle (deferred: mature daemons layer it on the idle timer, it needs per-OS memory probes, and the idle timer must work first). Documentation of `idle_exit_secs` tuning only (rejected: no value of the setting survives a polling fleet). Scheduled off-hours exit (rejected: arbitrary for a developer tool with no fixed hours).
- **Consequences:** A fleet that sends only cheap RPCs causes at most one exit and one respawn per `idle_exit_secs`. The respawn loads the baseline embedder eagerly (~4 s), and the first cheap RPC after exit pays that cost. A lazy baseline embedder would remove the cost and is a separate change. A session that only lists and reads can see the daemon exit between its requests; the next request respawns it.
